# Parrot UI taste review

日期：2026-06-16

## Design read

这是一个 macOS 菜单栏翻译工具，不是营销页。目标用户在阅读、写作和调试时频繁唤起它，所以界面要像系统工具一样克制、快速、可预测。

设计取向：

- Variance 4：遵循 macOS 原生布局，不做实验性构图。
- Motion 4：只做状态反馈和方向感，不做装饰动画。
- Density 7：信息密度偏高，但必须有明确主次。
- Accent：只使用 `#6D85C9` 低饱和紫蓝作为品牌强调色；红绿橙仅用于真实状态，实心强调底使用深色 ink。

## Current UI findings

1. 结果面板不应替用户判断哪一个引擎更“主要”。用户需要的是稳定顺序和可比较的结果列表，顺序应由设置页管理。
2. 视觉稿中使用 emoji 和手绘 SVG 图标，和 macOS 官方 App 的符号体系不一致。新的 HTML 稿改用文字符号和系统字形占位，SwiftUI 落地时映射 SF Symbols。
3. 设置页信息量增长很快，单一表单容易变成长列表。应改为系统设置式侧栏和分组详情。
4. 菜单栏入口如果只模拟 NSMenu，会丢失最近记录和快捷操作的上下文。Popover 更适合 Parrot 的轻量控制中心定位。
5. OCR 的真正增量不是重做系统截图框选，而是识别后的逐行选择。框选继续沿用系统交互，Parrot 只承接“选择哪些行去翻译”。
6. 红黄绿窗口控制只应出现在持久窗口上。结果面板、输入条、菜单栏弹出层是即时浮层，不提供最小化、缩放和长期驻留，所以不应使用 traffic lights。

## Redesign decisions

1. 结果面板采用顺序槽位结构：原文后按设置页「结果顺序」展示各引擎结果。异步返回只填充对应槽位，不区分主次。
2. 所有高频操作保留在原面板内完成：收藏、复制、朗读、重试、授权引导都不跳出上下文。
3. Pin 常驻是显式用户选择。默认保持失焦隐藏；点亮 Pin 后面板保持当前位置，不再因失焦消失，再次点击恢复临时浮层行为。
4. 输入翻译参考 Spotlight：单一输入焦点、语言方向胶囊、底部键盘提示。建议项只在有文本时出现。
5. 菜单栏 Popover 采用分组结构：主动作、最近记录、设置和退出。每行保持稳定命中区。
6. 菜单栏不展示引擎。引擎开关、密钥和结果顺序统一进入设置页，避免低频配置挤占即时入口。
7. 设置窗口参考 Apple 系统设置：左侧分区、右侧分组表。复杂引擎配置按翻译、密钥、快捷键、插件拆开。
8. 历史窗口参考 Finder/Notes 双栏结构：左侧检索，右侧复用结果阅读与操作。
9. OCR 结果卡默认全选识别行，允许用户剔除页码、页眉、噪声行后再翻译。
10. HTML 视觉稿里的图标使用统一 SVG sprite 作为 SF Symbols 语义占位。SwiftUI 实现时分别映射到 `pin` / `pin.fill`、`star.fill`、`doc.on.doc`、`speaker.wave.2`、`magnifyingglass`、`camera.viewfinder` 等系统符号。
