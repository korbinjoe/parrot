# Proposal: 重设计 Parrot macOS App UI 与交互

- **Change name**: `redesign-app-ui`
- **Status**: Proposed
- **Author**: ui-designer
- **Date**: 2026-06-15
- **依赖**: `macos-translator`（功能已落地，本提案只动表现层与交互，不改引擎/插件协议）

## Summary

对 Parrot 现有的四个 UI 界面（菜单栏下拉、悬浮结果面板、输入面板、设置窗口）做一次系统性视觉与交互重设计，补齐缺失的「历史/收藏浏览器」与「截图 OCR 取词浮层」，统一到一套遵循 **macOS Human Interface Guidelines / SwiftUI** 的设计语言里。本提案的核心交付物是**一份高保真、可交互的 HTML 视觉稿**（`mockups/index.html`），覆盖全部界面的明/暗模式与关键交互态，作为后续 SwiftUI 实现的像素级与交互级依据。

## Motivation

当前 UI 是「功能可用但缺乏设计统一性」的工程实现态，存在以下问题：

1. **视觉语言不统一**：结果面板用 `windowBackgroundColor` 灰块堆叠，设置窗口用 `.grouped` Form，菜单栏是裸 `NSMenu`，三者气质割裂，不像同一款产品。
2. **悬浮窗信息层级弱**：原文与多引擎结果都是同色灰卡片纵向平铺，缺乏主次；引擎名是 10px 三级灰小字，延迟 ms 与操作按钮挤在一行，扫读成本高。
3. **「即用即走」体验未做透**：面板出现/消失无过渡，多引擎异步返回时高度跳变，靠近光标定位但没有箭头指向来源，浮窗归属感弱。
4. **历史/收藏只有数据没有界面**：README 承诺历史/收藏检索，但代码中无独立浏览界面，收藏入口藏在结果面板的星标里，无法回看。
5. **未适配深色模式与动态字号**：硬编码字号（10/11/13/14px）与 `.red` 等直接色值，深色下对比与可读性无保证。
6. **缺少空/加载/错误态的设计规范**：仅文案兜底，无统一的骨架屏 / 占位 / 错误卡片样式。

重设计的目标不是「更花哨」，而是让 Parrot 在视觉和交互上**像一个原生 macOS 一等公民**——出现得克制、读得清楚、走得干净。

## Goals

1. **建立一套 macOS 原生设计 token**：基于 SF 字体阶梯、系统语义色（label/secondaryLabel/separator 等）、单一品牌强调色 `#6D85C9`、8pt 间距栅格、HIG 圆角与实色信息承载面，同时支持浅色/深色。
2. **重设计悬浮结果面板（核心）**：建立清晰的「语言方向 / 原文区 / 按设置顺序展示的引擎结果槽位」信息层级，不设主译文，不把返回顺序误读成优先级，加入出现淡入、失焦隐藏与 Pin 常驻。
3. **重设计输入翻译面板**：升级为 Spotlight 式命令条，支持语言方向切换（源→目标）、即时联想、回车翻译、`Esc` 关闭。
4. **菜单栏从裸 NSMenu 升级为轻量 Popover**：四大动作 + 最近 3 条历史 + 设置/历史入口；菜单栏不展示引擎配置。
5. **新增历史/收藏浏览器窗口**：列表 + 详情双栏，支持搜索、收藏筛选、语言对筛选、复制/朗读/再翻译。
6. **新增截图 OCR 取词浮层**：框选反馈、识别中态、识别结果可逐行选取后翻译。
7. **重设计设置窗口**：从单一 grouped Form 升级为「侧栏分区 + 内容面板」（通用 / 引擎 / 密钥 / 快捷键 / 插件 / 关于）。
8. **定义全部状态态样式**：加载（骨架屏）、空、错误、无网络、未授权（辅助功能权限）。
9. **交付可交互 HTML 视觉稿**：单文件 `index.html`，含明暗切换、悬停/聚焦/激活态、各界面切换，可在浏览器直接评审与逐帧对照实现。

## Non-goals

- **不改功能与架构**：不动 `TranslationProvider` 协议、引擎聚合逻辑、插件运行时、Keychain 存储。纯表现层 + 交互层。
- **不引入第三方 UI 框架**：实现阶段坚持 SwiftUI + AppKit 原生，HTML 仅为视觉稿，不是技术选型。
- **不做品牌 VI 重塑**：沿用 Parrot 名称与现有图标基调；本次聚焦界面，不做完整品牌手册（可作未来项）。
- **不做国际化文案重写**：视觉稿用现有中文文案，i18n 不在本次范围。
- **不承诺一次性实现全部界面**：HTML 视觉稿覆盖全部，但 SwiftUI 落地按 tasks.md 分阶段（悬浮面板优先）。

## Approach（概要，详见 design.md）

- **设计基线**：先读 macOS HIG 的窗口/材质/排版/颜色规范，再以「与系统其它 App 无缝」为准绳取舍。系统表面使用语义色，品牌强调色统一为 `#6D85C9`。
- **token 先行**：所有颜色/间距/圆角/字阶在 design.md 与 HTML 的 CSS 变量中集中定义，浅色一套、深色一套，SwiftUI 侧映射到 `Color(nsColor:)` 与语义色。
- **HTML 视觉稿作为契约**：用纯 HTML/CSS（+少量 JS 做主题切换与态切换）在 macOS 桌面背景上 1:1 还原每个窗口/浮层；信息承载面使用实色背景，只有系统菜单栏等 OS chrome 保留轻量材质感。审阅通过的 HTML 即为实现验收基准。
- **交互动效定义**：在 design.md 中以「触发 → 时长 → 缓动 → 位移」描述每个过渡，HTML 用 CSS transition 演示，SwiftUI 侧对应 `.animation`/`.transition`。
- **落地顺序**：悬浮结果面板 → 输入面板 → 菜单栏 Popover → 设置 → 历史/收藏 → OCR 浮层。

## Risks

| 风险 | 影响 | 缓解 |
|------|------|------|
| 实色信息面与系统材质之间的层次把握不当 | 可能显得灰、脏或禁用 | design.md 强制区分 `bgCanvas/bgPanel/bgContent/bgSidebar`，文字承载面不使用 `.regularMaterial` |
| 悬浮窗自适应高度 + 入场动画在 NSPanel 上易抖动 | 体验回退 | 沿用现有 `preferredContentSize` 自适应；动画只做 opacity+offset，不做高度补间 |
| 深色模式语义色映射遗漏导致对比不足 | 可读性 | token 表强制成对定义浅/深，评审走 WCAG AA 检查 |
| 范围含 6 个界面，易蔓延 | 交付延期 | HTML 全覆盖但 SwiftUI 分阶段，悬浮面板为 MVP 门禁 |
| 新增历史窗口/OCR 浮层涉及少量状态接线 | 超出纯表现层 | 仅定义 UI 与交互契约，数据接线由 fullstack-engineer 在 apply 阶段承接 |

## Reviewers

- code-reviewer / fullstack-engineer — HTML 视觉稿到 SwiftUI 的可落地性评审
- lead — 范围与优先级确认
